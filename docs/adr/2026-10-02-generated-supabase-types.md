# Supabase clients are typed with the generated schema
- Date: 2026-10-02
- Status: Accepted
- Area: data

## Context
Audit F7 (R-12, R-13, R-20, R-37, R-38, R-56; STRUCT-01, STRUCT-02, STRUCT-08). The three Supabase clients had no schema type, so every query result was `any` and about 45 call sites cast it by hand (`as { id: number }[]`, `as unknown as ...`). Several hand-written row types described the same table (`ChatRow`, `Cliente`, `StageRow`, `Linha*`, `Versao`) and drifted from the database: `chat_messages.created_at` and `dados_cliente.created_at` are nullable in the database while the app typed them as `string`, and `auth.ts` typed `agent_enabled` as nullable although the column is `NOT NULL`. `RouteContext` tsc errors came from `.next/types` not being generated before `tsc`.

## Decision
- `lib/database.types.ts` is generated by the Supabase MCP `generate_typescript_types` and never edited by hand. It is regenerated in the SAME delivery as every migration (`supabase/README.md`).
- The clients (`lib/supabase/{client,server,service}.ts`) use `DatabaseApp` (`lib/supabase/schema.ts`): `Database` with ONE adjustment, every SQL function argument also accepts `null`. The generator types arguments as `string` or `string | undefined`, but the code always sent `null` (all of them have `DEFAULT NULL`, and `pipeline_coluna.p_coluna` is passed null on purpose by the single-card lookup). `LinhaRpc` and `ArgsRpc` in the same file derive RPC rows and arguments, listing the columns SQL can return null (the generator types every RPC column as non-null).
- Row types come from `Tables<'x'>` and `Pick`. Domain types richer than a row keep their place (`lib/types.ts`) but derive the row part. A jsonb column is narrowed with a cast to the shape the app writes (`agent_config`, `tags`, `hours`); a domain object going INTO a jsonb column goes through `paraJson` (`lib/json.ts`), the one cast of that kind.
- Lib functions that receive a client take `Supa` (`lib/supabase/tipos.ts`), never the untyped `SupabaseClient`.
- `npm run typecheck` runs `next typegen && tsc --noEmit`, so `RouteContext` exists on a clean checkout.
- ESLint (`no-restricted-syntax`, warning) forbids `as unknown as`; the three remaining ones are library typing gaps with a written reason.

## Consequences
A migration that changes a column or function now breaks `tsc` until the types are regenerated, which is the point. RPC nullability is still declared by hand in `LinhaRpc` calls: the generator cannot know it. Status columns without a CHECK or enum (`knowledge_documents.status`, `handoffs.closed_how`, `prompt_mode`) stay `string`, so narrowing them to a union is still a field cast.

## Evidence
- Casts of query results and `as unknown as`: see the delivery report (before 167 cast sites in app/components/lib, after 122; `as unknown as` 6 to 3 with a reason).
- Real mismatch found and handled without changing runtime: `chat_messages.created_at` nullable (0 null rows today, default `now()`), `dados_cliente.created_at` nullable (0 null rows).
