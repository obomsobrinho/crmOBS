# Pairing code turned off: connect by QR only

- Date: 2026-10-17
- Status: Accepted (partially supersedes 2026-09-24-connect-by-pairing-code-and-risk-notice.md: the pairing code is no longer the default on mobile)
- Area: onboarding

## Context
The pairing code (connect by phone number, `POST connect-whatsapp` with `{ number }`) was never proven with a real number (`docs/handoff.md`). On 2026-10-17 the owner ran the full signup as a stranger on his phone, the day before inviting the first real testers, and the connect step failed:

- 5 attempts on the same number (DDD 33): 3 from the screen with the ninth digit, 2 generated by hand straight on Evolution (`GET /instance/connect/{instance}?number=`) without it, one of them from the clean `close` state. Every time WhatsApp answered "Não foi possível conectar" and the instance ended with `disconnectionReasonCode` 401.
- The QR code of the same number connected at the first try.
- Upstream: Evolution 2.3.7 (our server, `whatsappWebVersion` 2.3000.1050721289) has the exact report open, [evolution-api#2696](https://github.com/evolution-foundation/evolution-api/issues/2696). The cause, per [evolution-api#2727](https://github.com/evolution-foundation/evolution-api/pull/2727): around 2026-07-28 WhatsApp added a `companion_reg_refresh` stage to device linking that Baileys discards; no published Baileys release handles it (fix only in unmerged PRs, Baileys #2765 and #2602). The PR reports QR failing too for some; ours works.

On mobile the pairing code was the DEFAULT, so every tester signing up on a phone would have been stuck on the last step.

## Decision
- `components/ConnectWhatsApp.tsx` has `PAREAMENTO_LIGADO = false` (typed `boolean` so the code path keeps compiling): the mode is always `qr`, the "Conectar com número de telefone" link is gone.
- On mobile a notice (`data-slot="conectar-pelo-computador"`) says: if the WhatsApp that will answer is on this phone, open the page on a computer and read the QR with the phone. The QR still shows on mobile: a dedicated chip in ANOTHER phone reads it from there.
- The route keeps accepting `{ number }`; nothing server side changed.
- Turn it back on only after a real number connects by code (an Evolution release with the Baileys fix, or the patch of #2727 on our server). When it comes back, also apply the owner's notes of 17/10: the code shown first with a copy button, then "type this code in WhatsApp" (today the screen reads like the code arrives by message).

## Consequences
- Signing up entirely on a phone, with the attending number on that same phone, needs a computer for the last step. The invite text says so.
- Tests: `e2e/entrada.mobile.spec.ts` and `e2e/montagem.design.spec.ts` assert the QR-only screen and the mobile notice.
